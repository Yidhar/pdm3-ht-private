## Why step-100k here is not PAE-paper step-100k

The original PAE 80-epoch comparison config uses:

```text
100000 steps × global batch 1024 = 102.4M image presentations
```

The current run uses:

```text
100000 steps × global batch 96 = 9.6M image presentations
```

Therefore the current step-100k has only:

```text
96 / 1024 = 9.375%
```

of the original PAE 80-epoch sample budget. In PAE-paper-normalized terms, the current step-100k is roughly:

```text
100000 × 96 / 1024 ≈ 9375 official-batch steps
80 epochs × 0.09375 ≈ 7.5 epochs
```

This is why the first more comparable point remains approximately:

```text
100000 × 1024 / 96 ≈ 1,066,667 current-batch steps
```

Do not compare the current `100k @ batch96` result directly against the PAE paper's `100k @ batch1024 / 80ep` result.

## Why the absolute FID can still be large

Known protocol differences versus the PAE paper headline:

- Current metric is a local 5K generated / 5K real torchvision InceptionV3 pool2048 pass, not official 50K gFID.
- Current sampler is the active MeanFlow EMA sampler with `32` steps and no tuned CFG path in this anchor.
- PAE baseline generator configs use large-batch flow-matching transport, 250-step Euler sampling, tuned CFG scale/interval, and 50K samples.
- Current run is MeanFlow objective on PAE latents, not the original PAE transport recipe.
- Current live LR is constant `2e-4` at batch `96`; a lower/cosine MeanFlow-scaled schedule is planned as a control knob but has not been applied.

Therefore `FID=47.93` at the current early sample budget is concerning but not by itself a route-failure proof.

## Decision gate

Suggested interpretation once the step-150k 5K anchor finishes:

- If step-150k FID improves by several points versus `47.93`, keep the current constant-`2e-4` run as the main control and continue to the next anchor.
- If step-150k FID is flat or worse, treat this as stronger evidence of plateau / LR or sampler limitation. Do not hot-edit the live optimizer blindly; instead:
  1. preserve the current run as control;
  2. branch from the archived step-100k or step-150k checkpoint;
  3. test a lower/cosine LR schedule, e.g. MeanFlow batch-scaled `base_lr=7.5e-5`, `min_lr=7.5e-6`, `end_step=1.07M`, with a controlled ramp down if resuming from an optimizer checkpoint;
